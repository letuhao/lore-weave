# Claim rot — a document says the world is one way, and nothing asks the world

**Status:** 🟡 **DRAFT — for CLARIFY.** Not approved, not started. Written because
[`CLAIM-ROT`](../plans/2026-08-08-reality-layer-RUN-STATE.md) is a repo-wide check with a real
false-positive budget and a per-claim registration cost, and building it straight from a run-state
row would repeat the mistake it exists to catch.

**Reconciles:** `scripts/design-lint.py` · `scripts/gate-wiring-gate.py` · `scripts/closed-set-gate.py` · Locked Decisions ledger — §2 is the audit, and §3's constraints are `NV-1..6` applied to prose. *(This line first cited "Non-Vacuity", which is the standard's name but not a row's first cell in the index; `phase0-reconcile-gate` refused it as a phantom reference. A spec about claims that do not resolve, opening with a claim that did not resolve — recorded rather than quietly corrected.)* **The shape already exists five times in this repo and each instance covers one island.** `design-lint` verifies a *"N variants of X"* claim against the real Rust enum and refuses phantom "(registered …)" claims; `gate-wiring-gate`'s `KNOWN_RED` rows **fail when the gate turns green**; `dp-oracle-coverage-gate`'s `NO_PRODUCER` arms return a document to the denominator the moment a marker symbol appears; `deferral-gate` demands a `PROSE_ONLY` row say what would wake it; `actor-hub-figures-gate` measures every number one track's docs cite. What none of them covers is the sentence *"X does not exist"* in a run-state, an index, or a README — which is where all eight of this run's instances were.

---

## 1 · The defect, in one paragraph

A planning document states a fact about the repo — *"zero realities have ever existed"*, *"the meta
database does not exist"*, *"`loreweave` is the only login role"*, *"world-service has no server
binary"*. Someone builds the thing. **The sentence does not change**, because nothing connects it to
the thing it describes. The next reader treats it as current, because it is written as current and
sits in a file whose whole purpose is to be current. Every instance measured so far points the same
way — **claiming blocked what was built** — so the cost is not confusion but *work not done, or work
done twice*.

### 2.2 · **The obvious design does not work, and this is the finding that matters**

*"Grep the docs for `does not exist` / `is unbuilt` / `none` and verify each."*

```
grep -rlEi "does not exist|no producer|never been|zero .* have ever|is unbuilt|none serving"
  docs/plans docs/specs   ->  197 files
```

Sampling what that catches:

```
**+ a `precheck` method that does not exist anywhere yet**        <- a real claim
** -> SQL `column does not exist` -> the aggregate fails. **      <- quoted error text
**a row that does not exist**                                     <- a hypothetical in prose
** - "the adjudication register does not exist" | OK **           <- a CLOSED row, historical
```

Three of four are not claims about the current repo. **A prose-matching gate would be false
positives with a real one buried in them**, and a gate that cries wolf is a gate authors route
around — `gate-wiring-gate` exists because six CI legs sat red on `main` for four days and *"the
mechanism was never broken; nobody read the output."*

⇒ **Claims must be REGISTERED to be checked.** That is not a weakness of the design, it is what the
five working precedents all do.

### 2.3 · The five precedents, and precisely what each does not cover

| mechanism | binds | does not cover |
|---|---|---|
| `actor-hub-figures-gate` | a **number** a doc cites → a measurement command, scoped to marker-delimited windows in 4 files | non-numeric claims; any file outside its 4 |
| `design-lint` count-drift | *"N variants of `X`"* → the real Rust enum | claims not of that sentence shape |
| `design-lint` phantom-registration | *"(registered …)"* → the ownership matrix | anything not a registration |
| `gate-wiring-gate` `KNOWN_RED` | *"this gate is red"* → the gate's exit code, **failing when it goes green** | claims about anything but a gate |
| `dp-oracle-coverage-gate` `NO_PRODUCER` | *"this doc has no implementation"* → a comment-stripped source walk for marker symbols | claims about anything but a DP spec doc |
| `deferral-gate` `PROSE_ONLY` | *"this deferral has no mechanism"* → whether non-comment source names the id | the deferral's *subject* |

**The pattern across all six is identical and worth naming: a claim, a measurement, and an arm that
fires when they diverge — including when the claim becomes too pessimistic.** `KNOWN_RED` failing on
green is the exemplar; it is why the acknowledgement list shrinks instead of becoming permanent.

## 3 · What is proposed

A `claim:` annotation that a document carries inline, and one gate that resolves every one.

```markdown
| `G-S7a` | **Zero realities have ever existed.** <!-- claim: realities == 0 --> | ... |
```

```yaml
# contracts/claims/registry.yaml — the measurements, named once
realities:
  measure: sql
  dsn_env: CLAIM_META_DSN
  query: SELECT count(*) FROM reality_registry
  unmeasurable_when: the meta database is unreachable
```

The gate reads every `<!-- claim: … -->` in `docs/**`, resolves the measurement, and fails when the
assertion is false — **in both directions**, so *"zero realities"* fails at 10 and *"10 realities"*
fails at 7.

### Design constraints, each from a scar this repo already has

1. **Registered, not inferred** (§2.2). An unannotated sentence is out of scope, and the gate must
   say how many claims it resolved so *"0 claims checked"* cannot read as success — `NV-3`, and the
   exact failure the figures gate shipped once (*"passed silently when a marker string moved,
   reporting 'the docs agree' against zero subjects"*).
2. **`Unmeasurable` is never a commit blocker.** No Postgres, no `cargo`, no Docker ⇒ skip **that
   claim**, say so, exit 0. The figures gate crashed with a raw `FileNotFoundError` in a repo-wide
   hook and blocked frontend contributors on 47 services.
3. **A reach floor.** A walk that resolves nothing and a clean tree are byte-identical including the
   exit code.
4. **Both directions, and the pessimistic one especially.** Every instance in §2.1 was
   optimistic-for-work; `KNOWN_RED`'s lesson is that the arm which matters is the one firing when
   the claim becomes *too* pessimistic, because that is the one nobody looks for.
5. **`--self-test`, or it joins the 43** held at `GATE-TEETH-43`'s baseline.
6. **It must not become a second SSOT.** The registry holds *measurements*, never the answers.

### Deliberately NOT proposed

* **Backfilling 197 files.** The registry starts at the documents that decide work — measured-state
  tables and gate/blocker tables — and grows by use. A migration that must be complete to be
  correct will not be complete.
* **Retiring the five precedents.** Each is bitten and load-bearing. If this lands, they are
  candidates to *express* as claims later; that is a separate decision.

## 4 · Open questions for CLARIFY — the reason this is a draft

1. **Annotation or sidecar?** Inline `<!-- claim: -->` keeps claim and prose adjacent so they move
   together — but it edits 197 candidate documents over time and puts syntax in prose. A sidecar
   keeps documents clean and **guarantees the two drift**, which is this defect exactly.
2. **How much can a claim say?** `realities == 0` is trivial. *"`world-service` has no server
   binary"* needs a predicate over the repo. Does the registry hold shell/SQL snippets — and if so,
   is a gate that runs registered shell an acceptable surface?
3. **What is `unmeasurable` in CI?** If most measurements need a live Postgres, CI checks almost
   nothing while pre-commit checks a lot. That inverts where enforcement should be strongest.
4. **Does this earn its keep over just extending `actor-hub-figures-gate`'s scope?** Honest
   alternative: teach that gate more files and more shapes and never build this. It is narrower,
   already bitten, and already wired. **This spec's own §2.3 is the argument against — six islands
   is the problem — but the counter-argument is real and should be made properly rather than waved
   past.**
5. **Who owns a claim's registration** when the claim is in a run-state that a track abandons?
6. **What stops the registry rotting?** A measurement whose subject was deleted is a claim about
   nothing. It needs the treatment `deferral-gate` gives its own rows.

## 4b · AUDIT OF THIS SPEC (2026-08-11) — read before §4's questions, because it changes two of them

Audited against the tree the same way the run-state was. **Three factual errors of my own, one
design option I never considered, and a measurement that reduces the claimed value.** Recorded here
rather than silently corrected, because a spec about claims exceeding their evidence should not.

### The precedents in §2.3 — verified, and one is under-used

Four of the six characterisations check out verbatim in source: `KNOWN_RED` *"fails when the gate
turns green"* · `design-lint` count-drift *"VERIFIED against the real Rust enum"* · `PROSE_ONLY`
*"with a reason saying what would wake it up"* · `NO_PRODUCER`'s comment-and-string blanking.

**Two errors:**

* **`actor-hub-figures-gate` covers 3 files, not 4.** It has four SCOPES — the run-state carries two
  marker-delimited windows. Miscounted.
* **`design-lint`'s history is the strongest evidence in this spec and §2.3 flattens it to one
  line.** Its own docstring: *"a lint that cries wolf gets switched off, which is how this check
  spent its first life as INFO-only."* That is **empirical** support for §2.2, which currently
  argues the same point hypothetically. It also solved the case where a claim's subject does not
  exist in code (TWO SOURCES, `REC-98`), and it is deliberately **per-file** because three docs
  declare `pub enum ActorId` and *"a cross-doc comparison would false-positive on its first run"* —
  a direct warning to anything repo-wide. All three are load-bearing here and all three were lost.

### §2.2's ratio is not a measurement

*"Three of four hits are not claims about the current repo"* came from eyeballing **4 of 203**
matches, unrandomised, off a `head -8`. It reads as measured and is not. And the third category it
names — *"closed historical rows"* — is **1 of 203**, a category invented from a single example.
The conclusion (registration beats prose-matching) survives; the number supporting it does not.

### THE DESIGN FINDING — a simpler option exists and §3 never considers it

**Every one of the 13 measured-state rows already pairs a claim with a command, in the same row.**
The table is `| fact | value | command |`. For the file every track opens first, the registry §3
proposes **already exists as the table's own third column** — so the option is "run column 3,
compare to column 2", with no annotation syntax and no new file.

**And measuring that option is what makes this audit worth having, because it mostly fails:**

| the command as written | what it yields |
|---|---|
| `grep -c "^  <svc>:" infra/docker-compose.yml` | **0** — `<svc>` is a placeholder. It can never have been run as written. |
| `curl … …/internal/admin/token` | contains a literal `…` |
| `--list` | not a command |
| `docker compose ps meta-bridge`, `SELECT * FROM shard_utilization` | rows, against a prose value |
| `ls services/world-service/src/bin/`; `cat src/main.rs` | a file count, against **a paragraph** |

Roughly **5 of 13** rows have a command that is literally runnable and yields a comparable value.
Two contain placeholders that prove they were never executed. **The table looks like it carries
measurements and mostly does not** — which is the same defect one level down, and nothing found it
until this audit.

Worse for the proposal: **the `world-service` row — the instance that motivated all of this — is one
of the ones a column-3 check could not verify.** Its claim is three assertions in prose (it does not
serve · it is a scaffold · there are 7 bins) against a command that counts files.

### So the spec's worked example is the easy case, and §3 is built on it

`realities == 0` is a scalar. *"none serving — a 22-line `println!` scaffold; the 7 real bins are
workers/drills"* is not, and the hard part there is not annotation syntax — **it is that nobody has
decided what would falsify it.** §3 gives no account of non-scalar claims and §4 does not ask.

### Coverage, measured against §2.1's own eight instances

| | count | which |
|---|---|---|
| scalar or existence, in scope, **would be caught** | **5** | realities `7`, `G-S7a`, `G-S7b`, `G-S8a`, `G-S8b` |
| checkable but **out of the proposed scope** (`docs/**` only) | 1 | the Dockerfile comment — *"is `0008` in the manifest?"* is a boolean, in a `.Dockerfile` |
| **prose, not mechanisable as specified** | 2 | the `world-service` measured-state row; the `world-service` README |

**5 of 8**, and the 2 it misses are the two that survived longest — the README for *months*. Combined
with §5 (it catches the next reader, not the author who falsifies), the honest value is narrower
than §1 implies.

### What the audit recommends, for CLARIFY to accept or reject

**Q4 gets stronger, not weaker.** The thing that demonstrably works in this repo is *scalar figures
bound to runnable commands*, which is precisely `actor-hub-figures-gate`. The generalisation to
arbitrary prose claims is where every difficulty above lives.

A narrower v1 that the evidence actually supports:

1. **Reuse the `| fact | value | command |` shape as the registry** — it exists, authors already
   write it, and it puts claim and measurement adjacent by construction (§4 Q1 answers itself).
2. **Fix the two placeholder commands first**, and require column 3 to be runnable — that alone is a
   real finding this audit produced.
3. **Scalar and existence claims only.** Prose claims are declared OUT, with the reason, rather than
   promised and missed.
4. **Non-scalar rows must still be visible** — a row whose command is not runnable is reported as
   *unverifiable*, not skipped silently, or the table drifts exactly where it already did.

That covers 5 of 8 with near-zero new syntax. **What it does not cover is the two worst instances**,
and no honest version of this spec covers them with a gate.

## 5 · What this does not fix

Nothing here would have caught **the four instances this run created**, because I would not have
annotated a sentence I was about to falsify — the annotation goes on when the claim is *written*,
and the rot happens when someone *else's* work invalidates it. What it catches is the **next
reader**, and every instance in §2.1 was found by a reader, late, by luck. That is the honest scope:
it converts *"stale until someone happens to look"* into *"stale until the next commit touches the
repo"*, and it does not convert *"I falsified this"* into *"I noticed."*
