### `EVT-T1..T11` — the taxonomy (`03_event_taxonomy.md`)

**Active (6), all load-bearing.** The discriminating dimension the corpus chose is **origination mechanism**, not subject matter:

- **T1 Submitted** — an authorized actor emits with intent, via `dp::advance_turn`. Sub-types `PCTurn` / `NPCTurn` / `QuestOutcome`.
- **T3 Derived** — a side-effect state delta via `dp::t2_write`/`t3_write`; sub-typed by **`aggregate_type`**, not by name. 13 V1 aggregate types listed.
- **T4 System** — DP-internal lifecycle; 8 DP-locked sub-types; **zero validators**; unforgeable by feature code.
- **T5 Generated** — rule/aggregator/scheduler emits on **condition + probability + deterministic RNG**. Causal-refs **required**.
- **T6 Proposal** — untrusted pre-validation message; **bus-only, NOT in the event log**; three terminal states.
- **T8 Administrative** — operator via S5 dispatch; own validator chain (dual-actor, no A6).

**Retired (5), each with a recorded reason — this is the corpus at its best.** T2 NPCTurn → a T1 sub-type · T7 CalibrationEvent → a T3 sub-type · T9 QuestBeat → **split** across T1/T3/T5 because its three sub-shapes had three different mechanisms · T10 NPCRoutine and T11 WorldTick → both T5 `Scheduled:*`. The Option C collapse from "11 feature categories" to "6 mechanism categories" is the corpus's single most defensible move.

**Note:** `EVT-T12` was never allocated. The reserved range is T1..T11.

### `EVT-P1..P11` — producer rules (`04_producer_rules.md`) — **procedural throughout**

P1 (Submitted) · P3 (Derived) · P4 (System, DP-only) · P5 (Generated) · P6 (Proposal, `produce:[Proposal]` ONLY) · P8 (Administrative, admin-cli via S5). Five withdrawn mirroring the T* retirements. Adds one shape that bears on storage: the **uniform idempotency key** `(producer_service, client_request_id, target)` (`04_producer_rules.md:30-35`). The one genuinely load-bearing sentence is P1's **originator ≠ producer** split (`:63`) — the untrusted originator proposes, the trusted producer commits.

### `EVT-V1..V7` — validator framework (`05_validator_pipeline.md`)

V1 single linear pipeline, per-category subsets · V2 **5 fail modes** (`reject_hard` / `reject_soft_with_retry` / `sanitize_and_proceed` / `quarantine` / `warn_and_proceed`), `silent_drop` **forbidden** · V3 retry (rejection ⇒ no auto-retry; validator *error* ⇒ 3 retries → quarantine) · **V4 rejection-path** — a rejected turn **still commits** with `outcome=Rejected` via `t2_write`, and `turn_number` + `fiction_clock` do **not** advance · V5 hot-path pre-pipeline gates (<10ms, reject-only) · **V6 post-commit side-effects** — each is its own canonical `EVT-T3` with a causal-ref to its parent · V7 dead-letter framework.

**V4 and V6 are load-bearing for both questions.** V4 says a *refusal is an event*. V6 says a *consequence is a separate event*, not a field on its cause. The rest is procedural.

### `EVT-L1..L19` — lifecycle (four files)

- **L1..L6 (bus, `07_llm_proposal_bus.md`)** — Redis Streams via I13 outbox · reality-prefixed **per-cell** topics · lifecycle state machine with three terminals and ~60s retention · idempotency dedup on the uniform triple · **per-stream FIFO only**, cross-stream independent · fail-fast backpressure · shared dead-letter. **L2 is load-bearing** (*a proposal is never promoted in place; a fresh event is committed*); the rest is protocol.
- **L7..L11 (scheduler, `08_scheduled_events.md`)** — two trigger sources only (CalibrationEvent stream + FictionClockAdvance check), **no wall-clock** · beat registry with stable `beat_id`, **additive mutation only** · big-jump idempotency `(scheduler, reality_id, beat_id, fired_at_fiction_ts)` · fire-missed-beats-on-restart · V1/V1+30d/V2+ phasing. **L9 is load-bearing** (N threshold crossings ⇒ N firings, exactly once, in fiction-chronological order). The file is self-declared **V1 placeholder** (`08_scheduled_events.md:5`).
- **L12..L15 (causal, `09_causal_references.md`)** — the typed shape · single-reality + exists + **non-forward** + required-non-empty integrity checks · multi-parent is **inclusive AND**, soft cap 16 / hard 64 · **backward walks only**, bounded depth, acyclic by construction. **All four load-bearing for storage.**
- **L16..L19 (replay, `10_replay_semantics.md`)** — session catch-up = DP transport + a **category visibility filter** · canon-promotion replay (V2+ placeholder) · time-travel debug in **two modes** (structural-only = bit-deterministic; with-narration = explicitly NOT) · flavor handling across all three. **L18's two-mode split and L19 are load-bearing.**

### `EVT-S1..S6` — schema versioning (`11_schema_versioning.md`) — mostly procedural

S1 **two levels** (envelope `event_schema_version: u32` + implicit per-`(category, sub_shape)`) · S2 additive-emit-now / breaking-two-phase · **S3 upcasters are append-only and must be retained for the life of retention — indefinitely for `Forever`-tier events** · S4 bump triggers · S5 replay-invariance CI gate · S6 the EVT-S ↔ DP-C5 boundary. **S1 and S3 are load-bearing for storage**; the rest is process.

### `EVT-G1..G6` — generation framework (`12_generation_framework.md`)

G1 Generator Registry (declarative SSOT in the ownership matrix + a runtime view; `logical_id` + `blake3` UUID) · **G2 the 5-kind closed trigger taxonomy** — `CommittedEventOf` / `StateThresholdOn` / `FictionTimeMarker` / `OtherGeneratorOutput` / `LifecycleMarker` · **G3 cycle detection** (static topological sort at registration + runtime depth counter, hard cap 16) · G4 tiered capacity governance (50% warn / 90% page / 100% reject) · G5 coordinator = a **logical in-process role** per channel-writer, no new binary · G6 the 6-step extension procedure.

**G2 and G3 are load-bearing for *what IS an event* — G2 is the only place the corpus enumerates what can cause an event.** G1/G4/G5/G6 are procedural.

## PART 3 — THE GAPS

The two questions the new round must answer are **what IS an event** and **what do we STORE**. Here is what the corpus does not answer.

### G-1 · A game-world occurrence has no home in `EVT-T*`. **This is the central gap.**

A siege, a festival, a tribulation — the corpus can tell you the **mechanism** that emitted each message, and nothing else. Trace a siege through the taxonomy: the scheduler fires `EVT-T5 Generated / Scheduled:WorldTick` (`03_event_taxonomy.md:140`); a wall falls as `EVT-T3 Derived` on `aggregate_type=place`; an NPC's death is `EVT-T3` on `actor_status`; a PC's action inside it is `EVT-T1 Submitted`. **The siege itself is nowhere.** It is not a category, not a sub-type, not an aggregate — it is a *word for a set of causally related events across four categories*, and the corpus has no noun for that set.

Concretely, `EVT-T11_withdrawn` retired "WorldTick" **for being the same mechanism as NPCRoutine** (`:259-265`) — mechanically correct, and it is exactly the move that erased the world occurrence. The corpus discriminates on **origination**, which is a producer-side property; a siege is a **subject-side** concept.

This is the gap `D-98` names from the other direction: *"a closed set is MECHANISM if the engine's arithmetic DIFFERS PER MEMBER; it is A FEATURE'S VOCABULARY IN COSTUME if the engine treats members UNIFORMLY."* Apply `D-98`'s test to `EVT-T*`: does the engine's arithmetic differ across T1/T3/T5? **Only in which validator subset runs and which commit primitive is called** — and E-1 shows the first was removed as a security defect and E-4 shows the second does not exist. On the measured evidence, `EVT-T*` is a **producer-trust taxonomy** wearing an event-ontology's clothes. The new round should say so and decide what an event's *subject* identity is, separately.

There is also no **duration** concept. `fiction_ts_start` + `fiction_duration` (`06_per_category_contracts.md:35-36`) is the closest thing, and it is a field on an instantaneous message, not a span. A three-day siege is not expressible as one thing.

### G-2 · Transient vs durable is never stated as a distinction

The corpus makes **canonical vs non-canonical** (EVT-A8 — flavor is regenerable, not an event) and **committed vs bus-only** (EVT-T6 lives on the bus and *"NOT in the event log"*). Neither is the transient/durable axis. It never says which events are **short-lived facts** vs **permanent record**, and the three places that would need it are each silent:

- `EVT-S3` (`11_schema_versioning.md:82-88`) says upcasters must be kept for the life of retention and **indefinitely for `Forever`-tier** events — but the corpus never says **which** `EVT-T*` are `Forever`-tier. It defers to `S8-D3` retention tiers, which are not in this folder.
- `contracts/retention/event_classes.yaml` — which **exists and is shipped** — defines `canon_events` (never deleted) and `volatile_npc` (30 hot / 60 warm / archive), with an `event_type_map`. **No `EVT-T*` category maps to a retention class.** `D-63`'s **T1-2** records the same gap from the actor side, plus the `NV-2` defect beneath it: *"the canon CI gate is asserted against `retention-worker`, which never touches `events`, while `archive-worker`, which drops them, has zero class awareness."*
- `EVT-V4` (`05_validator_pipeline.md:80-89`) commits a **rejected** turn as a canonical event for audit completeness — a decision that only makes sense if some events are cheap and expirable, which the corpus has no way to say.

The one place the corpus almost gets there is `EVT-A8`, and the new round agrees with it (`D-23`: *"state that was never written is fabricated, may be lost, and did not matter — because nothing observed it"*). But A8's line is *canonical vs regenerable*, not *transient vs durable*.

### G-3 · Reaction chains: a seam is asserted, the mechanism is deferred, and three uncoordinated bounds now exist

**Cascade bounding — partially addressed, three ways, none authoritative.** EVT-G3 (`12_generation_framework.md:112-143`) gives static topological-sort cycle detection at registration plus a runtime depth counter capped at **16**. That is a real design. But:

- `33_trigger_group_order.md` is **SEALED 2026-07-28** with `TRG-A1..A18` + `TRG-L1..L6` + `TRG-R25..R29` — ordered resolution groups, `G3 REPLACE` as the one internally-ordered group, engine-owned group assignment, commutative-in-semantics/deterministic-in-iteration. It is three months newer and the event_model corpus does not reference it once.
- `D-79` fixes wave depth at **8** with `on_exceeded` engine-fixed to `Refuse` (`2026-08-02-actor-data-structure.md:577`).
- Neither of EVT-G3's two mechanisms exists in code (`GeneratorCycleDetected` 0, `cascade_depth` 0 — E-7).

**Reaction chains — not addressed at all.** The corpus's only reaction primitive is `EVT-G2` kind (d) `OtherGeneratorOutput` — a generator subscribing to a generator. There is no notion of a reaction that *intervenes* before a fact exists. The new round supplies exactly that and it has no counterpart in the corpus: `2026-08-02-actor-dataflow.md` §4.6.3 gives **propose → adjudicate → apply** with **two subscription points**, both on **status** —

| | subscribes to | may |
|---|---|---|
| **intervening** | `StatusProposed` | veto, replace, or add — **before** the fact exists |
| **reacting** | `StatusApplied` / `StatusCleared` | anything **except** unmake the fact |

— and §4.6.2 rules that **a threshold is not a subscription point**, because *"a trigger bound to a pool threshold re-embeds meaning in arithmetic."* §4.6.3 explicitly corrects the earlier framing: *"the propose→apply step is **not** the deferred part. It exists with zero reactions declared. `D-9` defers the reaction **vocabulary**, not the seam."*

**Nothing in `EVT-T*` can carry a `StatusProposed`.** It is not Submitted (no actor intent), not Derived (not a committed delta), not Generated (no probability), not System (not DP), not Proposal (not untrusted-origin), not Administrative. **This is the first concrete event the closed set cannot classify** — and it is the load-bearing event of the whole reaction design.

### G-4 · `EVT-G1..G6` — does it close "generate an event by condition + probability"?

**Partly. G2 and G3 are real design; G1, G4, G5, G6 are a framework with nothing behind it.**

What genuinely closes:
- **G2's 5-kind closed trigger taxonomy** is the corpus's best single contribution to *what causes an event*, and it is the **only** enumeration of causation anywhere in the corpus. Its closed-set proof (`:93`) is honest about being forward-looking. Kind (b) `StateThresholdOn` even anticipates the actor round's threshold layer.
- **G3's two-layer cycle detection** (static topological + runtime depth) is a correct design, independent of its cap being wrong (E-17).

What does not close — measured:
- **G1's registry**: the SSOT row exists (`01_feature_ownership_matrix.md:158`) but names its section wrongly, and **no registered generator carries `registry_uuid` or `capacity_ceiling`**, both marked ✅ required (E-8). `registry_uuid` 0 occurrences in source.
- **G4's capacity governance**: `generator_capacity_budgets.yaml` 0 · `GeneratorRateLimited` 0 · `EventModelError` 0. The tiered 50/90/100 policy has no enforcement point and no config file (E-7).
- **G5's coordinator**: 7 responsibilities and a failure-mode table, justified by a **false present-tense claim** — *"generators ALREADY run in-process per DP-Ch26"* — with no aggregator runtime in `crates/` (E-21).
- **G6's 6-step procedure**: steps 4 and 5 are the CI gates from E-7 and E-12. The procedure's enforcement half does not exist.

And the probability half is asserted through `dp::deterministic_rng`, which has **0 occurrences** (E-3). So *"generate an event by condition + probability"* has: a good condition taxonomy (G2), a good cycle bound (G3, wrongly sized), a registry with unpopulated required fields, and **no RNG, no capacity mechanism, no coordinator, and no gate**.

`_index.md:5` claims this *"RESOLVED at systematic level"*. The honest statement is: **the trigger vocabulary is resolved; the generation mechanism is designed and unbuilt.**

### G-5 · Four further gaps, stated briefly

- **No event↔ordinal identity story.** `D-46` establishes that a stored value's identity is answered by the reality's append-only **ordinal registry** and that rules-in-force is answered by `RulesPin`. The corpus's envelope has neither, and `EVT-S1`'s `event_schema_version` cannot detect the failure `D-43-orig` names: *"change a reality's declared quantity set and a stored `values[7] -= 30` remains shape-valid, upcasts cleanly, and now names a different quantity."* The shipped envelope's `ruleset_digest` (RLS-A13) is the field that addresses this, and the corpus does not know it exists (E-2).
- **No write/read ownership.** `D-37` (single writer, and the reason is **replay**) and `D-38` (**declared readers**, so a schema change's blast radius is computable) both cite `EVT-A4` as already stating the first — and `D-37` adds *"it is checked nowhere (`O-49`)."* The corpus has no read-set concept at all.
- **No relationship between an event and a delta.** `D-29` states it flatly: *"a modifier and a delta are the same thing at different times, and two fold rules for one concept is the defect this round keeps finding under other names."* The corpus's `EVT-T3 Derived` is a committed delta; `D-27`'s `ModifierRow` is an uncommitted one; nothing relates them.
- **No world- or group-scoped event.** `D-91`/`D-93` had to rule that a world-scoped quantity lives on the World **locus-actor** and a per-sect score is a **pair-keyed relation**. Every `EVT-T*` is reality- and channel-scoped with an aggregate key; there is no shape for *"this happened to the world."*

## PART 4 — WHAT SURVIVES

Inherit these. Do not re-decide them.

### Load-bearing and confirmed by the new round or by code

1. **`EVT-A10` — the event log is the SSOT; projections are derived (`02_invariants.md:197-219`).** Independently re-derived as `D-36` (*two SSOTs and only two*) and `D-23` (*canon is what is written to the ledger*), and **already implemented**: `crates/dp-kernel/src/load_aggregate.rs` folds events with a snapshot fast-path, and `contracts/migrations/.../0004_aggregate_snapshots_table.up.sql` states *"snapshots are a write-path cache, **not the SSOT**"*. `D-36` notes the kernel wrote this before the actor round derived it from Orleans. **Narrow the scope per E-14; keep the axiom.**

2. **`EVT-A8` — non-canonical regenerable content is NOT an event (`02_invariants.md:155-171`).** The reasoning still holds exactly as written: LLM text cannot be replayed verbatim, canon-checking 23 days of narration is cost-prohibitive, and the log would balloon. `D-23` reaches the same conclusion from the other side. **The best single idea in the corpus** and the one the new round should build the transient/durable line on top of (G-2).

3. **`EVT-A7` + `EVT-P6` — untrusted-origin producers emit proposals only.** Not just surviving: **hardened**. `services/commit-service/src/producer.rs` implements producer identity by HMAC-SHA256 over raw bytes precisely to stop a proposal electing its own trust tier. The axiom's *direction* was right and the implementation found the one way to get it wrong (E-1). Keep A7; replace A1's enforcement with producer-derived trust.

4. **`EVT-L1..L6` — the proposal bus.** The most shipped thing in the corpus. `services/commit-service/src/bus.rs:1-12` names the file it implements and delivers: `XGROUP CREATE … MKSTREAM` tolerating BUSYGROUP · **ACK only after successful processing** · `XAUTOCLAIM` stale-PEL reclaim · batched `XACK` · dead-letter to `<stream>:dead` after `max_attempts`. `spine.rs:187` uses `reality:{}:cell:{}:proposals` — **exactly EVT-L1's reality-prefixed per-cell granularity**. `admission.rs:56-80` implements EVT-L3's 60s dedup cache on the uniform triple. *(Cited as weaker evidence — outside `crates/`, though also outside `domain/`.)*

5. **`EVT-A9` — deterministic RNG for generated events.** The *rule* survives untouched and is reinforced everywhere: `D-8`'s byte-stable arithmetic, `D-52`'s single `1e-4` fixed-point scale, `D-51`'s slot-order iteration *"deterministic for replay by construction"*, `D-115`'s topological-order-by-ordinal. Only the named API is fiction (E-3).

6. **`EVT-V2` — the 5 fail modes, and `silent_drop` forbidden (`05_validator_pipeline.md:39-53`).** Nothing contradicts it and the discipline is independently praised: `D-86` records all four blind author agents naming **the refusal discipline** as the platform's best property — *"I have used engines that would have accepted all three and let me discover the truth in playtesting six weeks later."* Inherit the taxonomy wholesale.

7. **`EVT-V4` — a rejection is still a committed event; `turn_number` and `fiction_clock` do not advance (`:78-95`).** Resolves MV12-D11, is internally consistent, is contradicted by nothing, and answers a question the new round has not reached.

8. **`EVT-V6` — a post-commit side-effect is its OWN canonical event with a causal-ref to its parent (`:119-135`).** Structurally the same rule as `D-50`'s `commit_with_modifiers` (one call, one transaction, one `seq`) and `D-28`'s same-commit atomicity, both of which cite `PL_007` §8.4's *"runs **inside** the HolderCascade atomic batch, **not after it**"* — which is registered in `_boundaries/03_validator_pipeline_slots.md:137` as an EVT-V6 side-effect. **The corpus and the new round found the same rule from opposite ends.**

9. **`EVT-L9` — big-jump idempotency (`08_scheduled_events.md:63-79`).** `(scheduler, reality_id, beat_id, fired_at_fiction_ts)`; N threshold crossings ⇒ N firings, exactly once each, in fiction-chronological order; recurring beats get distinct keys because the fiction timestamp is in the key. The reasoning for **why a simpler key fails** is recorded (`:77`). Nothing supersedes it.

10. **`EVT-L8` — additive beat mutation (`:47-57`).** Moving a beat creates a NEW `beat_id` and Cancels the old, *"because mutating in place would break replay determinism — replaying the log would re-fire the OLD beat_id at the OLD threshold, which no longer exists."* This is `QTY-A5`'s never-reuse rule discovered independently three months earlier, and `D-45` proves the same discipline shipped for ordinals (`ruleset-loader/src/epoch.rs:154` `check_never_reused`, validate-before-append). **Generalise it; do not re-derive it.**

11. **`EVT-L18` — two replay modes, and the honesty about which is deterministic (`10_replay_semantics.md:79-97`).** Structural-only is bit-deterministic; with-narration is explicitly not; and `EVT-L19` forbids LLM regeneration in forensic context because *"it would mislead investigation with fresh-LLM output."* That last rule is a genuinely good call nothing else in the repo makes.

12. **`EVT-L12`/`L13`'s integrity rules — minus the type.** Same-reality-only, must-exist, **non-forward**, required-non-empty, acyclic-by-construction, bounded backward walks only. The column shipped (`0014_channel_ordering.up.sql:20`); the checks did not (E-6). The **rules** are right and are the cheapest thing on this list to build.

13. **`EVT-S3` — upcasters are append-only and permanent for `Forever`-tier events.** The reasoning is correct and matches `crates/dp-kernel/src/upcaster.rs`'s registry design. It needs G-2's retention classification to become actionable, and `D-61`'s snapshot-before-drop to be true at all (E-19).

14. **`EVT-G2` — the 5-kind closed trigger taxonomy.** The single most reusable artifact in the corpus. Only kind (d) `OtherGeneratorOutput` is contested (E-17's cascade bound), and kind (b) `StateThresholdOn` connects directly to the actor round's threshold layer. **Inherit it as the causation vocabulary and extend it for G-3's intervening/reacting split.**

15. **The Option C retirement discipline itself.** Five categories withdrawn with a recorded mechanical reason each, IDs never reused, migration path named per feature (`03_event_taxonomy.md:219-265`). The T9 QuestBeat split — *three sub-shapes with three different mechanisms, so one category was papering over the difference* — is the reasoning that should govern the new round's own taxonomy work.
