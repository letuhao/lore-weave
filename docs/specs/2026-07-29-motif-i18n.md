# Motif i18n — original language + translations, with fallback

**Date:** 2026-07-29 · **Size:** XL (logic 14, side-effects 3: DB migration, seed data, API shape)
**Branch:** `feat/frontend-tools-mcp-migration`

## Why

Today `motif.language` is part of the **identity key** (`uq_motif_system ON motif(code, language)`),
so a motif in two languages is **two unrelated rows**. Consequences measured live:

- **168 system rows for 84 motifs.** Every vector, every candidate slot, every link edge duplicated.
- **Wrong-language leak (dogfood, 2026-07-29):** an English book selected `mystery.witness_who_lies`
  and got the *Vietnamese* row; that Vietnamese summary went into the scene decomposer's prompt.
  Measured 3/15 library slots in the wrong language. A `_dedupe_by_code` mitigation was written but
  it only *picks better among duplicates* — it does not remove the duplication.
- **A new language means re-authoring 84 motifs**, not translating them. 18 FE locales exist; motif
  content exists in 2.

The identity of a motif is its `code` + structure. The language is a *view* of it.

## Design

### 1 · One motif, one row

`motif.language` → **`motif.original_language`** (parity with `books`/`chapters`). Identity keys drop
the language column:

| index | was | becomes |
|---|---|---|
| `uq_motif_system` | `(code, language)` | `(code)` |
| `uq_motif_user` | `(owner_user_id, code, language)` | `(owner_user_id, code)` |
| `uq_motif_user_book` | `(owner_user_id, book_id, code, language)` | `(owner_user_id, book_id, code)` |
| `uq_motif_book_shared` | `(book_id, code, language)` | `(book_id, code)` |

**Verified safe against live data:** 0 user code-collisions across languages; all 84 system `vi`
codes have an `en` twin; 0 `motif_application` rows point at a non-`en` motif.

Platform seed `original_language = 'en'` for all 84 — English is the platform source language.

### 2 · `motif_translation`

```sql
CREATE TABLE motif_translation (
  motif_id       UUID NOT NULL REFERENCES motif(id) ON DELETE CASCADE,
  language_code  TEXT NOT NULL,
  name           TEXT NOT NULL,
  summary        TEXT NOT NULL DEFAULT '',
  emotion_target TEXT,
  roles          JSONB NOT NULL DEFAULT '[]'::jsonb,  -- [{key,label,constraints}] — key MUST match source
  beats          JSONB NOT NULL DEFAULT '[]'::jsonb,  -- [{key,label,intent}]      — key MUST match source
  preconditions  JSONB NOT NULL DEFAULT '[]'::jsonb,  -- [{text}] positional
  effects        JSONB NOT NULL DEFAULT '[]'::jsonb,
  examples       JSONB NOT NULL DEFAULT '[]'::jsonb,
  source_content_hash TEXT NOT NULL,   -- hash of the SOURCE translatable payload this came from
  source         TEXT NOT NULL DEFAULT 'machine' CHECK (source IN ('authored','machine')),
  translated_by  TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (motif_id, language_code)
);
```

**Translated:** `name`, `summary`, `emotion_target`, `roles[].label`, `roles[].constraints[]`,
`beats[].label`, `beats[].intent`, `preconditions[].text`, `effects[].text`, `examples[].text`.

**Never translated** (structure/identity — lives only on the source row): `code`, `kind`,
`category` (machine taxonomy — `romance.proximity`), `genre_tags`, `roles[].key`, `roles[].actant`,
`beats[].key`, `beats[].tension_target`, `beats[].order`, `tension_target`, `annotations`,
`info_asymmetry`.

**Why PK `(motif_id, language_code)` and not glossary's `(…, source_content_hash)`:** glossary caches
*snapshots*, which legitimately have concurrent versions, so the hash belongs in its key. A motif has
exactly one current text per language — hash-in-key would give unbounded row growth and turn the
fallback into a "pick the newest matching" subquery. Keeping the hash as a **column** preserves the
staleness guarantee while the read stays a single `LEFT JOIN`. This mirrors what `motif` already does
for vectors: `embedded_summary_hash` is a column, not a key.

### 3 · Resolution — never fail, never blank

```
resolve(motif, want_language):
  want == motif.original_language        → source fields          (text_language = original)
  fresh translation (hash matches)       → translated fields      (text_language = want)
  stale translation (hash differs)       → translated fields      (text_language = want, stale=true)
  no translation                         → source fields          (text_language = original, fallback=true)
```

The response carries **`text_language`** and **`text_fallback`**. Today's wrong-language brief was
silent; after this it is impossible for a caller — model or FE — to receive text without knowing what
language it is in. (Repo rule: a degrade-safe path must surface "unverified".)

### 4 · Embedding — unchanged, source only

One vector per motif, built from the **original-language** `motif_summary_text`. bge-m3 is
multilingual; cross-language retrieval already works and is not part of this change. Translations are
never embedded.

Corollary: collapsing 168 → 84 rows halves the vector set and **removes the wrong-language candidate
leak at the root**. The `_dedupe_by_code` mitigation is deleted, not kept.

### 5 · Who pays for a translation

| Tier | `original_language` | Translations |
|---|---|---|
| **Platform seed** | `en` (all 84) | Pre-translated to all 17 targets at **dev time**, committed as seed files, free to every user |
| **User-authored** | whatever they wrote in | **None.** No auto-translate, no token spend, ever |
| **Shared / adopted** | carries the origin's | The **adopter** pays for their own demand languages |

Same posture as a book: the platform ships its own content translated; a user's content is theirs and
is never machine-translated behind their back or on the platform's dime.

### 6 · Seed layout

```
seed_motif_packs/
  romance.json                  ← SOURCE (en) — the only place structure lives
  mystery.json  …               ← 10 packs
  translations/
    vi/romance.json             ← {code: {name, summary, beats:{key:{label,intent}}, …}}
    ja/romance.json  …
```

A translation file carries **only translatable leaves keyed by `code` + beat/role `key`**. It cannot
add or drop a motif and cannot change structure — enforced at load.

The 10 existing hand-written `*_vi.json` packs convert to `translations/vi/*.json` with
`source='authored'`, which locks them against machine overwrite (mirrors `i18n_translate.py`'s carry
rule). They are literary Vietnamese, not machine output; discarding them would be a quality loss.

### 7 · The translation tool

`scripts/motif_translate.py` — a clone of `scripts/i18n_translate.py`, reusing its proven machinery:
flatten/unflatten, chunk-by-key-count, verify (key-set identity · placeholder parity · target-script),
self-heal on hard failures, isolate-retry on soft, gap-fill resume, `_FAILED.json` no-silent-drop.

Deltas from the i18n original:
- Source is the seed packs, not locale JSON.
- **Key-invariance is a HARD failure** — a drifted `beats[].key` would silently break the merge.
- Domain prompt = narrative-craft terms (beat / motif / arc / reversal), not UI terms.
- Structure leaves are refused, not passed through.

Dev-time authoring script ⇒ same provider-gateway exemption as `i18n_translate.py` (output is
committed static content, not service runtime).

**The user-paid runtime path is a separate slice** — it needs job plumbing + metering + a UI
affordance, and it MUST go through provider-registry. It is not built in this cycle; the policy it
serves ("we never translate user motifs for free") is what this cycle implements. Tracked, not
silently dropped.

## Data migration (forward-only)

| # | Step | Expected |
|---|---|---|
| M1 | Add `original_language` (← `language`); create `motif_translation` | — |
| M2 | For each system code: `en` row is the keeper; copy the `vi` twin's translatable fields into `motif_translation(keeper, 'vi', source='authored')` | 84 rows |
| M3 | Repoint `motif_link` edges off `vi` rows onto the `en` twin, `ON CONFLICT DO NOTHING` | 55 edges, expected ~all dropped as duplicates of existing `en` edges |
| M4 | Repoint `motif_application` off `vi` rows (defensive) | 0 rows (verified) |
| M5 | Delete the 84 `vi` system rows | 168 → 84 |
| M6 | Rebuild the 4 unique indexes without `language`; drop `language` | — |
| M7 | User rows: `original_language = language`, no collapse, no translation | 55 en + 4 vi untouched |

**Migration gates (must be pasted as evidence, not asserted):** system codes 84 before → 84 after ·
every pre-migration `vi` text reachable through the translation lookup · 0 orphaned
`motif_application` · `en`-side link edge count unchanged · no motif left with a NULL/empty resolved
name in either language.

## Out of scope

- Embedding / retrieval scoring semantics (explicitly excluded by the request).
- The user-paid runtime translate job (separate slice, tracked).
- The 4 user-authored `vi` motifs stay exactly as they are — `original_language='vi'`, untranslated.
