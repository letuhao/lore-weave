## Structural guarantees (not discipline)

- `apply` only reachable via `step()` → true because **Island owns `D::State`** and exposes only
  `&State`; no external `&mut` path exists.
- No ambient time: seen-TTL and timers take `Tick` arguments; crate never reads a clock.
- No `f32` anywhere in state or events (TDIL-A9).

## S2 milestone (2026-07-27, user-directed long-run to completion): multi-island

Spec surface: §9 (IslandMessage) · §10 (lifecycle/dissolution/handoff) · §10.5 (recovery).
Design calls (recorded before build):

1. **`dissolve(self, reason) -> Dissolution<D>` CONSUMES the island** — `Gone` is made
   structurally unrepresentable by move semantics instead of a runtime lifecycle flag. The host's
   map loses the island by ownership transfer; no "submitted to a gone island" path can exist.
2. **Cross-island exactly-once (I8) reuses the seen-set** — `deliver()` maps `delivery_id` →
   `input_id`; the existing I2 dedup IS the exactly-once mechanism. No new machinery.
3. **+1-tick latency is the ROUTER's property, not the kernel's** (spec §9: "the host chooses
   the transport"). The reference router (`Realm`, in `crates/sim` — SC-A7: kernel holds no
   island registry) buffers a message sent during tick T and delivers at T+1's tick boundary.
   Missing/dissolved target → discarded **with a recorded reason** at the router, never an error.
4. **Handoff seam = `Domain::Portable` + `extract`/`install`** (SL-A12). `depart(id)` removes
   the registry entry *before* any message can exist → entity-in-exactly-one-island is
   structural. In-flight inputs for a departed entity fail `EntityAlive`/`IslandOwns` (already
   built, S1a).
5. **Checkpoint = state + registries + seen + rng + gen + tick; pending work is EXCLUDED** —
   §10.5's loss table is the contract (buffered intents lost, in-flight LLM decisions
   self-heal via deadline fallback). `restore()` rebuilds a stepping-identical island.
   Quarantined pills are returned in `Dissolution`, NEVER re-queued (SC-A9).
6. Dissolution pending-work policy per §10.1: transfer-class (`Migrating`/`NodeShuttingDown`)
   drains queue+schedule+buffered into `Dissolution::transferable`; discard-class
   (`Resolved`/`MemoryPressure`/`Failed`/`Unresponsive`/`Idle`) counts them as discarded.
