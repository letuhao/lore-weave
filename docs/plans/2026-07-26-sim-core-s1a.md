## ⚠ Found during PLAN — the predicted panic trap is REAL here

Workspace `Cargo.toml` `[profile.release]` sets **`panic = "abort"`** — the exact pattern docs 14/15
warn about by name. Harmless for S1a (tests run dev profile), **fatal for S3**: commit-service in
release would abort instead of catching, killing containment. **S3 gate item:** commit-service ships
under a profile with `panic = "unwind"` (dedicated profile or workspace change — owner decision),
and the S1b CI check asserts it.

## Structural guarantees (not discipline)

- `apply` only reachable via `step()` → true because **Island owns `D::State`** and exposes only
  `&State`; no external `&mut` path exists.
- No ambient time: seen-TTL and timers take `Tick` arguments; crate never reads a clock.
- No `f32` anywhere in state or events (TDIL-A9).
