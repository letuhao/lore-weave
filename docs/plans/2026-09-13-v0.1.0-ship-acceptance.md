# v0.1.0 — ship acceptance criteria

> **✅ APPROVED by the PO, 2026-09-13.** All twelve criteria stand as the ship bar for v0.1.0.
> **Nothing is built or published until the PO says so** — `main` containing v0.1.0 is not shipping,
> and the PO holds the ship decision regardless of what this board says.
>
> **Standing verdict: v0.1.0 is NOT shippable.** Five criteria are not met and four have never been
> assessed. The bar does not move to suit the schedule; the work moves to meet the bar.

is the finding. Two criteria are marked ❓ because I do not know the answer and will not guess.

## What the statuses add up to

**Three met.** The claims are honest, the naming is honest, and the findings from the last human
run are closed with evidence. That is real, and it is the work of the last two days.

**Five not met, and none is exotic.** Two red tests, a broken CI leg, an unpatched vulnerability
with an available fix, an unaccepted one without, and 197 strings nobody has read.

**Four unknown, and those are the ones that matter most.** Whether the product does its core job,
whether it builds and publishes at all, and whether it can be rolled back, are unanswered — not
failing, *unasked*. AC-11 is the sharpest: the release act has never been rehearsed.

**The honest summary: v0.1.0 cannot be declared shippable today, and the blocker is not defect
count — it is that the most important criteria have never been tested.**

## Proposed order, if the PO accepts this bar

Cheapest first, and deliberately: AC-11 before AC-9 before AC-10, because a build that does not run
makes every other answer moot, and a browser journey needs something to run against.

1. **AC-11** — attempt a build and publish to a throwaway target. It has never been tried.
2. **AC-4, AC-5** — the two red tests and the MinIO image. Both are small and both are blocking.
3. **AC-9** — the persona journeys against that build.
4. **AC-10** — the PO drives the real journey, as on 2026-09-06.
5. **AC-6, AC-8** — the `datasets` bump, the written acceptance of `rsa`, and the string review.
6. **AC-7** — confirm `govulncheck` runs once the fix merges.
7. **AC-12** — write and exercise the rollback.

## How these criteria get met

By the **remediation cycle** — see [Remediation Cycle](../standards/remediation-cycle.md). Each
cycle is one pass of *investigate → post issues → fix → prove the fix → update the criteria*, and
`scripts/remediation-cycle-gate.py` refuses a criterion that flips to `✅ met` without all five.

The cycle log for this release lives in `## Cycles` below. **A criterion is never edited in place
without a cycle entry explaining the move** — that is how a bar quietly relaxes.

**AC-10 remains the PO's**, and no agent can settle it: whether an author can really plan and draft
a book with canon intact is a judgement made by writing one.

## Cycles

### Cycle 1 — dependency vulnerabilities, the non-breaking half

**Investigated:** ran `npm audit` against all **nine** lockfiles rather than trusting CI's summary, plus `pip-audit` and `cargo audit`. Measured before touching anything: **2 critical, 52 high, 68 moderate, 22 low** across npm. The split matters more than the total. The frontend's critical (`vitest`) and high (`vite`) are **dev tooling** — exploitable against a developer's machine when the test UI or dev server listens, not against a user. The 43 highs across the four gateways are **server runtime on the request path**, including CRLF injection in `http-proxy-middleware`, which is the proxying layer itself, plus `lodash` code injection and `ws` memory disclosure. `datasets 2.21.0` sits in knowledge-service's RUNTIME requirements while being reached only by deferred imports in quality-eval tests.

**Issues:** #247 (gateway runtime highs), #248 (`datasets`), #249 (frontend dev tooling, and the shipped `react-router` open redirect), #250 (`rsa`, no fix exists — needs a named person)

**Fix:** `npm audit fix --package-lock-only` across six packages, applying only non-breaking upgrades. Lockfiles changed; no manifest did. Plus `datasets` 2.21.0 → 5.0.1.

**Proof:**

### Cycle 2 — the two red tests, and the CI leg that could not start

**Investigated:** read the failures rather than the counts. Neither was what its message said. The two chat-service failures reported *"corpus looks truncated"*, but the corpus was ABSENT: `docs/eval/toolloop/` is tracked because two reading-rule notes live in it, while the recorded `*.json` runs are not, so a `CORPUS.exists()` guard said "present" and the loader found nothing. `DB live-smoke` was not a failing test at all — exit 125 is docker refusing to pull `minio/minio`, which is no longer anonymously pullable. Both are NV-3 in shape: a check whose scope never reaches its subject.

**Issues:** none — both are internal CI and test-harness defects with no user-facing behaviour and no public record needed. The four security issues from Cycle 1 (#247, #248, #249, #250) remain the open record.

**Fix:** the skip guard now tests for actual runs rather than a directory; the MinIO image is repointed to quay.io and PINNED, at all six call sites.
