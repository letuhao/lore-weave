# v0.1.0 — ship acceptance criteria

Reconciles: Plan Acceptance Criteria · Remediation Cycle · Non-Vacuity · Versioning & Releases — this plan does not add a rule. It APPLIES those four to one release: the criteria are the AC-1..7 shape, each move is an RC-1..6 cycle, every `met` rests on a check that can fail per NV-6, and what "ship" means is Versioning & Releases' definition rather than a new one. It is the instance, not the standard.

> **✅ APPROVED by the PO, 2026-09-13.** All twelve criteria stand as the ship bar for v0.1.0.
> **Nothing is built or published until the PO says so** — `main` containing v0.1.0 is not shipping,
> and the PO holds the ship decision regardless of what this board says.
>
> **Standing verdict: v0.1.0 is NOT shippable.** Five criteria are not met and four have never been
> assessed. The bar does not move to suit the schedule; the work moves to meet the bar.

## How these criteria get met

By the **remediation cycle** — see [Remediation Cycle](../standards/remediation-cycle.md). Each
cycle is one pass of *investigate → post issues → fix → prove the fix → update the criteria*, and
`scripts/remediation-cycle-gate.py` refuses a criterion that flips to `✅ met` without all five.

The cycle log for this release lives in `## Cycles` below. **A criterion is never edited in place
without a cycle entry explaining the move** — that is how a bar quietly relaxes.

**AC-10 remains the PO's**, and no agent can settle it: whether an author can really plan and draft
a book with canon intact is a judgement made by writing one.

### Cycle 6 — rollback, asked for the first time

**Investigated:** no rollback path existed anywhere — not in `versioning-and-releases.md`, not in the runbooks, not in the go-live checklist. The interesting half is not the image mechanism, it is the schema. The novel-platform services do **not** use versioned migrations: six of them run an idempotent `CREATE TABLE IF NOT EXISTS` blob at startup, so there is **no down path at all** and the schema only moves forward. That blob is cumulative and does contain non-additive statements — `RENAME COLUMN max_spend_usd TO max_spend_tokens`, `RENAME COLUMN language TO original_language`, `DROP TABLE IF EXISTS source_corpus`. **Issues:** none — nothing is broken. A missing runbook is an absence, and filing an issue to write a document that this cycle writes would be bookkeeping.

### Cycle 12 — teaching the runner a third answer, so a skip stops reading as a pass

**Investigated:** T16, which Cycle 11 left open on the grounds that the fix was "a protocol change

is almost never — so it now runs on every self-test instead.

why: `NEEDS_STACK` decides membership statically while this precondition is dynamic, so it would
convert a true red on a stacked box into a permanent skip; and exit 2 would have made CI
permanently red. **The gate knows whether it could look. Nothing else does** — which is why the
answer belongs in its exit code.
