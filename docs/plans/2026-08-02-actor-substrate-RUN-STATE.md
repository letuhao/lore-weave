### 4d. PO decisions 2026-08-02 — sealed

| # | Decision |
|---|---|
| **D-22** | **A transfer is island-local, and remote trade is a DIFFERENT FEATURE.** The atomic two-delta primitive requires both actors in one island; a cross-island attempt is refused by name. Auction houses, banking and remote markets belong to **trade + economy**, are **per-reality**, and are built from escrow and order books — mechanisms the transfer primitive was never meant to supply. Treating the refusal as a lost capability was a scope error: it is a **boundary**, not a limitation. Exactly-once handoff (Photon) stays recorded as a kernel growth path; **actor core does not need it.** |
| **D-27** | **A CONTRIBUTION IS DATA, NEVER CODE — `CPL-A17` generalised, and it is the whole decoupling design.** A feature does **not run during the tick**; it leaves **rows**, and the engine folds rows. **This collapses `D-25`'s two channels into one**: a feature owns tables, and one table shape (`ModifierRow`: actor · target ordinal · op · magnitude · layer · condition · source · expiry) is understood by the engine. **The engine never calls a feature, never enumerates features, never learns that "equipment" is a word** — it validates the row *shape* (target granted · op in the closed set · layer declared · condition names a declared threshold) and nothing else. The three alternatives all fail: a plugin registry makes the engine depend on features and makes replay load-order-dependent; **a single designated projector concentrates the coupling instead of removing it and grows without bound — §12.5's god-object collapse relocated one file over**; a runtime handshake is inverted but still order-dependent. External practice states it flatly: *systems should never have dependencies on each other*. **The test that a registry fails and this passes: a feature contributing NOTHING (opinion, titles, journeys) needs no opt-out, no null implementation, no registration — absence is free**, which is what lets the architecture survive features nobody has thought of. |
| **D-28** | **Staleness is made IMPOSSIBLE, not detectable: a modifier row is written and removed in the SAME COMMIT as the feature row that justifies it.** Equip writes `actor_equipment` **and** its modifier rows in one commit; unequip removes both in one commit. There is no sync step to forget because there is no second step — so no epoch, no invalidation window, no re-materialiser, no checker. **The corpus already validated this shape once**: `PL_007` §8.4's equipment clearing runs *"**inside** the `EF_001` HolderCascade atomic batch, **not after it**"*, for the identical reason. `D-16`'s L2 persistence service is what makes it cheap — both writes were already going to one place through one commit. Removal is **by `source`**, never by matching values, which also makes *"why is my attack 47"* answerable — the same causes-not-levels property recorded for the relational family. |
| **D-29** | **A conditional modifier's condition is a DECLARED THRESHOLD, never a predicate grammar.** *"+10 attack while below 30% hp"* tempts a predicate language over ordinals — and a grammar with nesting **is a scripting language, which is `CPL-A17` violated by the very mechanism meant to honour it**. We need none: a threshold is already the concept, already declared by the reality, already evaluated, and already sitting in `ActorQuantities.threshold_active`, so `condition: Option<ThresholdOrdinal>` costs **one bit test** and adds nothing to design, validate, sandbox or bound. Stacking policy (full / highest-only / diminishing) is **declared vocabulary**, matching `PL_006`'s existing per-flag policy. |
| **D-30** | **The acceptance test for the architecture: adding a feature must touch ZERO files in actor core.** No engine edit, no registry entry, no struct field, no reserved ordinal, no projector edit — so `size_of::<ActorQuantities>()` never moves and `D-26`'s anti-accretion gate is never approached. **A feature that cannot be added without touching actor core is the design failing, and the feature is telling us so** — the same signal as `D-24` at feature scale and `D-25` at field scale, now at architecture scale. |

### 4e. The two omissions the PO caught 2026-08-02 — measured, not asserted

The PO named two gaps this round had walked past for eight turns: **(1)** the data lifecycle from kernel to
FE, across many modules and many storage forms, plus multi-layer caching — *a game that does not define

results:

| # | Decision / finding |
|---|---|

## 7. The revised DF7-A4 (D-8) — text to apply in S3

```
DF7-A4 (Byte-stable arithmetic) — REVISED 2026-08-02.

A value that enters a digest or a replayed comparison must have exactly one
byte representation per value. Fixed-point i64 milli-units get this for free,
which is why stat resolution uses them: those numbers are integers on a fixed
scale, so NaN, -0.0 and rounding order simply do not arise.

This is NOT a ban on floating point. IEEE 754 basic operations (+ - * / sqrt)
are correctly rounded and reproduce bit-for-bit on any conforming target; Rust
enables neither fast-math nor FMA contraction, and x86-64/ARM64 both mandate
SSE2/NEON. `world-gen` uses f64 across 41 files and
`civ_bundle_hash_is_deterministic_per_seed` hashes its output - float and a
stable digest coexist in this repo today.

Forbidden in the replayed path are the three things that genuinely do not
reproduce:
  1. transcendental libm functions (sin, cos, exp, ln, powf) - IEEE 754 does
     not require correct rounding for these and implementations differ;
  2. order-dependent reductions - a sum folded in a different order differs;
     this bites when WE parallelise, not from the compiler;
  3. unnormalised NaN / -0.0 reaching hashed bytes - canonicalise or exclude.

Choose the representation by what the number IS, not by fear of float:
integers on a fixed scale -> fixed-point; continuous fields over a wide
dynamic range -> float.
```

  must land this round: a monotonic sequence in the event (chaos stamps whole seconds and then sorts by
  them), an idempotency key over canonical bytes (chaos uses `DefaultHasher`, explicitly unstable across
  Rust releases), per-actor threshold **edge state** (`F1` — without it every tick below the line re-emits),
  and the applied-effect payload + ruleset version on the actor (`F5`/`F10`).

### 🔴 The single biggest omission — **context-scoped rule overlays**

chaos resolves rules against **where the actor currently is**: `area_overrides` + `pvp_overrides`, precedence
`pvp_template → area → global` (`exhaustion_config_loader.rs:19-22,117-146`), and a whole golden vector on it.

**Our document resolves rules exactly twice** — manifest load, then spawn. The words *area*, *zone*,
*arena*, *context*, *instance* do not appear. And `PO-2` **actively forecloses** the third: *"after spawn
the actor does not consult it."* Arena rules softening death · a safe zone suppressing a threshold ·
a dungeon modifier · a PvP flag · a sect-territory qi bonus · a `Locus` village under siege — **all
inexpressible**. The Bethesda analogy carries the counter-example: a base form is fetched at spawn, but a
**cell still applies its own rules to whatever walks into it**.

**The fix is small and closes `A-1` at the same time.** A live actor resolves rules as
`digest-pinned manifest ⊕ context overlay`, the overlay being a declared, ordered, digest-identified
stack; the actor stores **overlay identity + applied-effect payloads** alongside its diverged state. Then
*"what rules is this actor running under"* = `(ruleset digest, overlay stack digest, applied effects)` —
all on the actor. `F5`/`F10` get their home, and the passivate/restore test gets a real subject.
Far cheaper now than after copy-at-spawn is built.
