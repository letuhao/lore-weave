## 4. No dev-only secret/default is reachable with no override path

Audited every `INTERNAL_SERVICE_TOKEN`, `JWT_SECRET`, and `_change_me`/`dev_*`-shaped default
in `infra/docker-compose.yml`. Two outcomes, one of them a real, fixed gap:

- **`JWT_SECRET`, `DIARY_ENCRYPTION_KEY`, and 12 other secrets** already used
  `${VAR:-dev_default}` compose interpolation — a real deployer sets `.env` (documented in
  `infra/.env.example`, with `DIARY_ENCRYPTION_KEY` marked REQUIRED for non-local deployment)
  and the default never reaches a real deployment. **PASS as designed.**
- **`MINIO_ROOT_USER`/`MINIO_ROOT_PASSWORD`** (the `minio` service itself) and **6 of 9**
  service-side `MINIO_ACCESS_KEY`/`MINIO_SECRET_KEY` pairs (`book-service`,
  `provider-registry-service`, `chat-service`, `lore-enrichment-service`,
  `lore-enrichment-worker`, `worker-infra`) were **hardcoded literals with NO override path at
  all** — setting an env var would have done nothing. **This was a real go-live blocker, found
  by this checklist and fixed in this cycle**, not deferred:
  - Parameterized all 7 to `${MINIO_ACCESS_KEY:-loreweave}` / `${MINIO_SECRET_KEY:-...}`,
    matching the 3 client blocks that already did this correctly.
  - The server (`minio`) and every client now read the *same* two override variables, so one
    env-var pair rotates the credential everywhere — a split default (server hardcoded,
    clients overridable) would have let an operator "set" a new secret the server never
    honored, locking every service out.
  - Documented all 8 previously-undocumented secrets (`INTERNAL_SERVICE_TOKEN`,
    `ADMIN_TOKEN_ISSUER_SECRET`, `ADMIN_AUDIT_HMAC_KEY`, `CONFIRM_TOKEN_SIGNING_SECRET`,
    `AGENT_REGISTRY_VAULT_KEY`, `LLM_PAYLOAD_ENCRYPTION_KEY`, `MINIO_ACCESS_KEY`,
    `MINIO_SECRET_KEY`) in `infra/.env.example` — mechanically overridable before this cycle in
    most cases, but invisible to a deployer who only reads the example file.
  - BITE: confirmed the default resolves unchanged with no env vars set (server + clients both
    still `loreweave`/`loreweave_dev_minio_secret`), then set
    `MINIO_ACCESS_KEY=testuser MINIO_SECRET_KEY=testsecret123` and confirmed `docker compose
    config` shows the override reaching the server's `MINIO_ROOT_USER`/`MINIO_ROOT_PASSWORD`
    **and** every client's `MINIO_ACCESS_KEY`/`MINIO_SECRET_KEY` — proving the fix, not just
    the absence of an error.
  - `METAWORKER_BRIDGE_TOKEN` was checked and correctly excluded from this audit — it's used
    only by `orphan-scanner`/`world-service`/`publisher`/`meta-bridge`, all profile-gated to
    the opt-in `game`/`full` track, not part of v0.1.0's default shipped scope.

**PASS, after a fix.** Every default-scope secret now has a documented, unambiguous override
path. Not itself a runtime fail-safe (nothing refuses to start on a default secret the way
`game-server`'s `assertWsAuthConfig` does for `LW_WS_REDIS_URL`) — recorded here as a real
difference in posture, not silently assumed equivalent; a future hardening pass could add that
assertion, but building it wasn't this checklist's job.

## 5. `LICENSE` — AGPLv3, present and correct, and consistent repo-wide

```
$ head -2 LICENSE
                    GNU AFFERO GENERAL PUBLIC LICENSE
                       Version 3, 19 November 2007
$ grep -n license README.md
7:[License: AGPL v3 badge] -> https://www.gnu.org/licenses/agpl-3.0
349:- License: AGPL-3.0-or-later (LICENSE) -- contributions are under the same terms
```

**PASS** for everything actually published as one of the 33 release-target images.

**Resolved, not just observed:** the *root* `package.json` (`loreweave-monorepo-game` — the
pnpm workspace root for the game/MMORPG client, explicitly **not** the novel-writing-platform
workspace per its own `description` field) and five other packages (`frontend-game`,
`services/game-server`, `packages/api-types`, `packages/auth-client`, `packages/design-tokens`,
`packages/i18n`) declared `"license": "MIT"`, inconsistent with the project-wide AGPLv3 the
reviewer confirmed this release ships under. None of the six is one of v0.1.0's 33
release-target images, but the inconsistency was real and GitHub-visible regardless. Fixed:
all 7 `package.json` files (the root plus the six above) now declare
`"license": "AGPL-3.0-or-later"`, matching `LICENSE` and `README.md`'s own declaration exactly.
Verified: `grep -rn '"license": "MIT"' --include=package.json .` returns zero matches
repo-wide; all 7 edited files still parse as valid JSON.
