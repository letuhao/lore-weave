glossary_propose_batch: `ops` is a required array with typed items, so the generic sweep's three
cases all died in schema validation ("ops must not be empty", then "validating /properties/ops")
and never reached the book. Re-probed with a well-formed op whose `type` was READ from the enum
[adopt_genres|create_kinds|add_attributes|...] — my first attempt used {kind,name}, which is the
shape of a DIFFERENT tool's item:
  absent   refused   book not accessible
  tenancy  refused   book not accessible   (IDENTICAL — no existence oracle)
  empty    refused   book_id must be a UUID   (named)

memory_timeline's "🔴 SUCCEEDED" on the EMPTY case is NOT a boundary failure. required=[] — there is
no field to empty, so the case degenerates to an argument-less call, and returning the ambient
project's timeline is exactly right for a zero-argument read. Its real boundary IS exercised by the
other two: an absent project and a foreign project both refuse "project not found", identically.
