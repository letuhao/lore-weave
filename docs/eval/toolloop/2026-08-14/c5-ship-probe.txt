🔴 AND A CORRECTION TO MYSELF, recorded because I came within one commit of filing it as a platform
defect. I read these schemas with a helper that did `inner = list($defs.values())[0] if $defs else s`
— it takes the NESTED type whenever a tool has $defs at all. For kg_ontology_propose that made me
read `KgSyncDecision` (node_type/code/choice) as the tool's own arguments, conclude that the
published schema "does not describe the tool the server implements", and start writing up a serious
catalogue defect. The schema is FINE: its top-level properties include op, verb, level, project_id,
decisions and more, and required is ['op'] with op ∈ [schema_edit, adopt_template, sync_apply].
69 of the 315 catalogue tools carry $defs, so that reader would have misread any of them.
