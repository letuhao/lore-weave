composition_motif_bind_edit (op-dispatch: only `op` required, so the generic cases never touched an
id). Re-probed with op=bind read from the enum [bind|unbind] plus project_id/node_id/motif_id:

memory_forget's "🔴 SUCCEEDED" on absent and tenancy is NOT a boundary failure. It returns
{"invalidated": false, "reason": "no matching fact found"} — a soft no-op with an honest payload
rather than a refusal, IDENTICAL for an absent id and a foreign one, so it is no existence oracle
and it invalidates nothing. The probe cannot tell a truthful no-op from a boundary that does not
hold; a human has to. Recorded as exercised and SOUND.

jobs_get's empty case refuses, but it leaks a RAW DRIVER ERROR to the caller:
  invalid input for query argument $2: '' (invalid UUID '': length must be between 32..36 characters, got 0)
That is asyncpg's message, not the platform's. It refuses correctly and no boundary is crossed, so
it is not a SHIP failure — but every other refusal measured in this loop names the field and the
next move, and this one names a query argument position. Noted, not filed as a defect.
